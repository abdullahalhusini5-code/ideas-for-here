What the four layers are

One file, three things that read it.

The scan is architecture, not anatomy. Colour is the only claim: where a fact lives, and who is allowed to change it.

01

Memory

ideas.json — every brief, area, time bucket and free piece. The only source of truth.

02

03

The voice

The conversation

Connect an agent

The MCP server, step by step.

Seven steps, about five minutes. Reading needs no permissions; writing needs you to drop one flag and mean it.

  1. 1

    Check Node

    You need Node 18 or newer. Nothing else — no packages, no keys.

    node -v
    node -v

    If that prints v18 or higher, you are ready. If not, install the current LTS from nodejs.org.

  2. 2

    Stand in the project folder

    Open a terminal where ideas.json lives. The server resolves the catalog relative to itself, so the folder matters, not the terminal.

    cd C:\path\to\ideas-for-here
    cd C:\path\to\ideas-for-here

    Use your real path. In the rest of this guide, replace C:\path\to\ideas-for-here with it.

  3. 3

    Start the server

    This serves the page, a live catalog, and the MCP endpoint on one port. Leave the terminal open.

    node server.mjs --port 4173
    node server.mjs --port 4173

    Open 127.0.0.1:4173 to confirm the catalog loads. The same process answers /api/ideas and /mcp.

    Add --read-only to refuse every write. Do that for a first run, or when lending the screen to someone.

    With node server.mjs running, connect to the URL instead of spawning a process. Example for Claude Code:

    claude mcp add --transport http ideas-http http://127.0.0.1:4173/mcp
    claude mcp add --transport http ideas-http http://127.0.0.1:4173/mcp

    It answers POST only — no SSE stream — and sends no CORS headers, so another web page cannot call it. Non-browser clients are unaffected.

    Keep the backslashes doubled inside JSON. If the client cannot find node, use its absolute path (where node shows it).

  5. 5

    Ask it something real

    The agent now has eight tools. These three exercises cover search, a full brief, and the planning prompt:

    • “Search the catalog for ideas about a water cut in my building.” → ideas_search
    • “Give me the full brief for garden-calendar, including the honest catch.” → ideas_get
    • “Use plan-a-local-app for meter-reader, for a neighbour who is not technical.”

    Every answer includes a page link such as ?idea=meter-reader, so the agent can send a person straight to the right card.

  6. 6

    Let it write — only if you mean it

    Stop the server, remove --read-only from the client config or the command, and start again. Then ask:

    • “Add an idea about the school run — three steps, one free piece, plain English. Then validate the catalog.”
    • “Change the tagline of garden-calendar and show me what changed.”

    The write is validated first, then replaces ideas.json atomically. Refresh 127.0.0.1:4173 to see it — the page reads the live API when the server is running.

    Writes touch only your copy on disk. The public GitHub Pages site is read-only and always will be; a commit is still how a change reaches it.

  7. 7

    Prove it works

    Two checks, no framework, no network for the first one:

    node tools\test-mcp.mjs
node tools\check-links.js
    node tools\test-mcp.mjs
node tools\check-links.js

    Expect 35 passed, 0 failed and all links OK. The suite drives both transports and writes only to temporary copies of the catalog.

Prompt
plan-a-local-app — one brief into a one-weekend plan

Where it cannot go

GitHub Pages runs no Node process. The public site is data-driven but read-only: the page fetches ideas.json, and there is no /mcp there.

MCP needs a local checkout or a host you control. Keep it on 127.0.0.1; there is no authentication, and writing is a real file edit.
